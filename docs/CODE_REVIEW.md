# 代码检查记录

检查日期：2026-10-22（Asia/Hong_Kong）。修复基于 v1.2.0，现已纳入 v1.3.0 源码。

## 检查范围

检查了监控与延迟接口、RPC/REST 回退、旧版 WebSocket、数据归一化、定时刷新与清理、三页路由及独立显示配置、主机详情、流量与到期日期、图表和地球生命周期、主题清单、打包脚本与发布工作流。依赖另通过 npm audit 检查。

## 已修复

| 问题 | 影响与处理 |
| --- | --- |
| 暂停时手动刷新与任务发现存在竞态 | 新测试点返回后会中断旧记录请求，手动刷新标记却已消耗。现在等待任务发现完成，并保留标记至记录加载成功。 |
| 标签页重新可见时重复调度轮询 | 实时请求尚未完成时，第二次 poll 会另外安排定时器。现在同一轮询生命周期内只允许一个执行中的 poll。 |
| 全部延迟目标请求失败仍更新采集时间 | 旧数据可能看起来刚采集完成。现在保留最后一次成功加载的时间，并显示错误。 |
| 关闭详情或切换历史范围未取消请求 | 旧请求虽然不会覆盖新状态，但仍占用连接。现在通过 AbortController 取消 RPC 或 REST 历史请求。 |
| 非对象 JSON 响应未校验 | null 等响应会抛出内部 TypeError。现在统一返回可处理的 ApiError，不触发兼容回退。 |
| 可选主机元数据类型未经约束 | 非字符串 tags 会在 split 时导致页面报错。现在归一化标签、公开备注、到期日期、排序权重及流量额度。 |
| 单向流量依赖双向计数器 | 仅统计上传或下载时，另一方向缺失也会导致额度用量为空。现在只要求对应方向的计数器。 |
